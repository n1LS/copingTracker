# copingTracker — Key Combinations Reference

This document lists every key / key combination handled by the UI **view classes**
(`sources/Application/Views/**`). It was generated by reading every
`ButtonDown()` / `ButtonUp()` / `OnButtonOverride()` implementation in the codebase.

Input is expressed as a **button event** (`ButtonMask` in
`BaseClasses/View.h`). Every press (and every auto-repeat of a held direction)
calls `ButtonDown(newButton, mask)`: `newButton` is the single button that
triggered the event and `mask` holds the *other* buttons already held (never
`newButton` itself). Every release calls `ButtonUp(button, mask)` with the
released button and what is still held afterwards.

A chord is matched **exactly**: `newButton` plus the exact set of held buttons
(`IsChord(newButton, mask, trigger, held)`). `EDIT+UP` means UP pressed while
only EDIT is held. A combination no view defines does nothing, so holding
RIGHT and pressing UP no longer moves in two directions at once and a second
direction is ignored.

> **Audit status:** sections 3.1–3.5 (Song, Chain, Phrase, Table, Groove) were checked
> against the code on 2026-11-17. The other sections were written before the input
> handler rewrite and have not been re-checked since.
>
> **Navigation chords** (`NAV + direction`) are routed by `View::ProcessButton` to the
> view's `navigationDown()` *before* `ButtonDown()` runs, so they work in every mode
> (selection, clone, new, ...). Where `navigationDown()` does not handle a direction,
> the press falls through to `ButtonDown()` as usual.
>
> **NAV double tap** (`NAV + NAV`): press, release and press `NAV` again within 300 ms,
> with no other button used in between. `View::ProcessButton` detects it before
> `ButtonDown()` and calls the view's `OnNavDoubleTap()`; a view that does not override it
> gets the press as a normal `NAV` press. A `NAV` that was used as a modifier (for example
> `NAV + LEFT`) never counts as a tap. Currently used by the phrase view and the piano roll
> view to toggle between each other.
>
> **The phrase slot:** the phrase view and the piano roll share one place in the navigation
> map. `ViewData::phraseViewType_` remembers which of the two was used last, and every
> view that leads there (`NAV + RIGHT` in the chain view, `NAV + LEFT` in the instrument view,
> `NAV + UP` in the table view, `NAV + DOWN` in the groove view) opens that one
> (`ScreenView::NavigateToPhrase`). The toggle itself always goes to the other view.
>
> Both views derive from `PhraseEditingView`, which implements the input they share:
> `NAV + direction`, `NAV + NAV`, `PLAY`, `NAV + PLAY` and `EDIT + direction` (switching the phrase).
>
> **Undo / redo:** `ALT + EDIT` opens a menu of actions in the song, chain, phrase, piano roll, table and groove view. The menu stays
> open while `ALT` is held (`EDIT` can be let go): `LEFT` undoes, `RIGHT` redoes (a held arrow repeats), in the song, chain and phrase
> view `ENTER` clones and `UP` / `DOWN` start a selection. While the menu is open `ALT + LEFT / RIGHT` are undo / redo, not
> their usual action (tempo nudge, piano roll fields). Letting go of `ALT` ends the menu; after an undo / redo it does not start a
> selection, as it does from the clone mode without one. The menu of every view has a legend with the undo keys (`SongClone`, `ChainClone`, `PhraseCloneInstrument`, `PhraseCloneTable`,
> `PhraseMenu`, `TableMenu`, `RollMenu`, `GrooveMenu`); in the table and piano roll view it only has undo / redo and the selection. `View::ProcessButton` handles it before the view sees the key, so it works in
> every mode; the mode that `ALT + EDIT` armed (clone, selection) ends. Every button press, with everything it triggers (also
> in a modal), is one entry of the history (`UndoJournal`, a ring of `UNDO_BUFFER_SIZE` = 6144 bytes, the oldest
> entries are dropped when it is full; a press that does not fit at all clears it and shows "Undo history cleared").
> Presses of the same buttons within 800 ms that change the same memory merge into one entry, so a value that is
> changed by several presses is undone in one go. Covered: song rows, chains, phrases, tables and grooves. Not covered:
> instruments (their variables, creating, cloning), project variables, samples, config. The history is cleared when a
> project is loaded. The data classes only hand out writable memory through `Edit...` accessors that record it first.
>
> **Context legend:** in clone and selection mode (in the song view also while the loop is
> being selected, legend `SongLoop`, and in the song, chain and phrase view while a mute / solo
> chord is held, legend `SoloMute`) the song, chain, phrase and table
> views replace the notes / command help in the bottom info area with a legend of the
> available combos. The legends live in `tools/manual/raw_data/ContextLegends.copingDoc`
> and must be kept in sync with the tables below.
>
> **Chord hints:** while a single button is held in the song, chain, phrase, table or groove view (`ALT`, `NAV`, `EDIT` or `ENTER`,
> not an arrow; `PLAY` has no chords) the info area shows the chords that can follow once the button has been held for 250 ms (a tap never shows it, `View::kChordHintDelayMs`), legends `SongChordsAlt` / `Nav` / `Edit` /
> `Enter` and the same with `Chain`, `Phrase`, `Table`, `Groove` and `Roll` (the second table view has its own `Table2ChordsNav`; in the
> piano roll they are only shown while the grid has the focus). Any other legend (menu, selection, mute / solo, loop) takes priority, and the hint is gone as soon as a
> second button is down or the button is released. While a modal is open (the command picker) the part of the screen it does not
> cover does not change: no hint is shown and the buttons of the modal do not change it.

Chords made only of ALT / NAV / EDIT have no natural trigger, so either key may
be the last one pressed (`IsPair(...)`): `EDIT+ALT`, `EDIT+NAV`, `NAV+ALT`,
`NAV+EDIT`. These are
marked *either order* below. Everything else is triggered by ENTER, PLAY or a
direction.

In the tables, **Type** is `chord` (exact match), `chord, either order`, or
`release` (fires from `ButtonUp`).

## 1. Button / Host-key reference

| Device button | Bit / constant | Host keyboard key |
|---------------|----------------|-------------------|
| UP            | `BM_UP`    (1<<3) | `↑` (Up arrow)        |
| DOWN          | `BM_DOWN`  (1<<1) | `↓` (Down arrow)      |
| LEFT          | `BM_LEFT`  (1<<0) | `←` (Left arrow)      |
| RIGHT         | `BM_RIGHT` (1<<2) | `→` (Right arrow)     |
| ALT           | `BM_ALT`   (1<<4) | `A`                   |
| NAV           | `BM_NAV`   (1<<7) | `S`                   |
| EDIT          | `BM_EDIT`  (1<<5) | `E`                   |
| ENTER         | `BM_ENTER` (1<<6) | `D`                   |
| PLAY          | `BM_PLAY`  (1<<8) | `Space`               |

> Host mapping lives in `sources/Adapters/Host/system/input.cpp` (`scanKeys()`).
> On the device the same buttons are physical keys / virtual (mirrorUI) buttons.

In the tables below a **modifier** is one of `ALT`, `NAV`, `EDIT`, `ENTER`;
a **direction** is one of `UP`, `DOWN`, `LEFT`, `RIGHT`.

> Subclass `SampleImportView` adds more combos — see §14.

`SelectProjectView` has three tabs at the bottom: **Load**, **Rename** and **Delete** (`LEFT / RIGHT` select one, `ENTER` activates it).
**Rename** opens the on screen keyboard (`TextInputModal`, as the project name field of the project view) with the name of the
selected project in it. With Ok the project (its directory in the projects folder) is renamed if it can be: the name has to
be a name (not empty, none of the characters `\ / : * ? " < > |`, spaces around it are dropped), it has to be a different one,
no project has it already (upper and lower case are the same on the card, only the case of a name can change) and it is not the
project that is loaded (that one is saved to its directory). A toast tells how it went (success or the reason). The projects
are scanned again and the renamed one is selected.
**Load** asks "Load song and lose changes?" first. If the project has an autosave file a second box asks which one to load, with the
buttons **Autosave** (selected, the autosave is newer than the project file) and **Project** (`LEFT / RIGHT` select, `ENTER` confirms).
The answer is the `useAutosave` argument of `PersistencyService::Load`: the boot state file (`.current`) gets the project name, and a
second line `project` when the project file was chosen, then the system reboots into the project. At boot `LoadCurrentProjectName`
reads both (`BootUseAutosave()`), and `SaveProjectState` clears the request again once the project is open. Loading never removes the
autosave file, only saving the project does.

### 2.4 Value fields (`UIIntField`, `UIIntVarField`, `UIHexVarField`, ...)
Generic value editing reached through `FieldView`:
`ENTER+arrow` = change value, `ENTER+EDIT` = reset to default (only when modified).

### 3.2 `ChainView` (`Views/ChainView.cpp`)

Modes: `VM_NEW`, `VM_CLONE`, `VM_SELECTION`.

Columns: the phrase, the transposition (hex and signed decimal) and the **scale-aware** flag (`Sc`, drawn `char_symbol_indicatorFull_s`
when on, `char_symbol_indicatorEmpty_s` when off). When a note is played (`transposeNote` in `Scale.cpp`): instruments that are not
transposable (`IsTransposable()`) play the note as it is; otherwise the transposition of the chain row is added, with the flag on the
result is mapped into the scale of the project (a note that is not in the scale moves to the next note of the scale in the direction of
the chain transposition: up with a positive one, down with a negative one, the nearest, downwards on a tie, without transposition),
and last the transposition of the project is added, it moves everything and is not mapped. The notes in the phrases are never changed.
The flags of a chain are one 16 bit mask (`Chain::ScaleAwareMask`, bit n is row n), saved as `"scale-aware"` of the chain.

*Normal mode*

| Combination | Type | Action |
|-------------|------|--------|
| `EDIT + LEFT / RIGHT` | chord | Warp to neighbouring chain (`warpToNeighbour`) |
| `EDIT + UP / DOWN` | chord | Warp within current chain column (`warpInColumn`; UP=−1, DOWN=+1) |
| `ENTER + EDIT` | chord | Cut phrase at cursor (`cutPosition`) |
| `EDIT + ALT` | chord, either order | Enter **clone mode** |
| `EDIT + NAV` | chord, either order | Toggle mute, taken back when `EDIT` is let go while `NAV` is held (see appendix) |
| `ENTER + DOWN` | chord | Phrase value −`0x10` (row col) / −`0x0C` (transposition); scale-aware column: switch the flag off |
| `ENTER + UP` | chord | Phrase value +`0x10` / +`0x0C`; scale-aware column: switch the flag on |
| `ENTER + LEFT` | chord | Phrase value −`0x01`; scale-aware column: switch the flag off |
| `ENTER + RIGHT` | chord | Phrase value +`0x01`; scale-aware column: switch the flag on |
| `ENTER + ALT` | chord | Paste clipboard (`pasteClipboard`) |
| `ENTER` alone | chord | Paste last phrase into slot; in the phrase column (column 0) it also arms `VM_NEW`; in the scale-aware column it toggles the flag |
| `ENTER + NAV` | chord | Toggle solo, taken back when `ENTER` is let go while `NAV` is held; a kept solo ends with the next `ENTER + NAV` (see appendix) |
| `NAV + LEFT` | chord | Navigate → **Song view** |
| `NAV + RIGHT` | chord | Navigate → **Phrase view** (current phrase) |
| `NAV + PLAY` | chord | Start chain with retrig (`startImmediate`-style, `PM_CHAIN`) |
| `NAV + ALT` | chord, either order | Un-mute all |
| `NAV + DOWN` | chord | Open **Generator wizard** (`GeneratorWizardModal`) |
| `PLAY` | chord | Start chain playback (`PM_CHAIN`, no retrig) |
| `DOWN / UP / LEFT / RIGHT` | chord | Move cursor |
| `ENTER` release (phrase-in-progress) | release | Finalize the phrase step edit (marks phrase step as used) |

*Clone mode (`VM_CLONE`)* — entered with `EDIT + ALT`, legend `ChainClone`:

| Combination | Type | Action |
|-------------|------|--------|

| any other button | chord | Leaves clone mode and starts a **selection**; the button is then handled as in selection mode |
| `ALT` released | release | Leaves clone mode and starts the **selection** at the cursor right away (cloning needs `ALT` held, so there is nothing to clone any more); the selection legend is shown |

*New mode (`VM_NEW`)* — armed by `ENTER` alone in the phrase column:

| Combination | Type | Action |
|-------------|------|--------|
| `ENTER` alone | chord | Put the next free phrase into the slot |

*Selection mode* — legend `ChainSelection`:

| Combination | Type | Action |
|-------------|------|--------|
| `EDIT` alone | chord | Copy selection |
| `EDIT + NAV` | chord, either order | Toggle mute |
| `EDIT + ALT` | chord, either order | Extend selection |

The selection and the cursor move with it; at the first / last row nothing happens |

### 3.3 `PhraseView` (`Views/PhraseView.cpp`)

The **volume** is `1`–`F` or none (there is no volume `0`: `LEFT` below `1` gives none, `RIGHT` on none gives `1`, `UP` is `F`, `DOWN` is none), the **instrument** is `00`–`1F` or none and a **command** is one of the 32 commands (their token values are `0`–`31`, `0`–`63` are reserved for them). Every other token is `64` or higher. Save files made before this change do not load.

Modes: `VM_NEW`, `VM_CLONE`, `VM_SELECTION`.

*Normal mode*

| Combination | Type | Action |
|-------------|------|--------|
| `ALT + EDIT + ENTER` | chord | Clone the instrument (or table) under the cursor (`cloneInstrument` / clone table), independent of clone mode |
| `EDIT + LEFT / RIGHT` | chord | Warp to neighbouring instrument column / table column (`warpToNeighbour`) |
| `EDIT + UP / DOWN` | chord | Warp to previous / next instrument (`warpInChain`) |
| `ENTER + EDIT` | chord | Cut value at cursor (`cutPosition`) |
| `EDIT + ALT` | chord, either order | Enter **clone mode** (`VM_CLONE`) |
| `EDIT + NAV` | chord, either order | Toggle mute, taken back when `EDIT` is let go while `NAV` is held (see appendix) |
| `ENTER + DOWN / UP / LEFT / RIGHT` | chord | Adjust cursor value (`updateCursorValue`). In the note column LEFT / RIGHT move the note one semitone down / up (`changeNote`, any note can be entered, the scale of the project does not change it), UP / DOWN move it an octave. Notes that are not in the scale and key of the project are drawn in `Theme::SemanticColors::offScale`, unless the instrument of the step is not transposable. Other columns: DOWN / LEFT decrease, UP / RIGHT increase |
| `ENTER + ALT` | chord | Paste clipboard (`pasteClipboard`) |
| `ENTER` alone | chord | Paste last value; on command columns a **command picker** opens (if enabled); on the instrument and command value columns arms `VM_NEW`; on the note, instrument and volume columns starts **audition** (hold ENTER, release stops) |
| `ENTER + NAV` | chord | Toggle solo, taken back when `ENTER` is let go while `NAV` is held; a kept solo ends with the next `ENTER + NAV` (see appendix) |
| `NAV + LEFT` | chord | Navigate → **Chain view** |
| `NAV + RIGHT` | chord | Navigate → **Instrument view** |
| `NAV + DOWN` | chord | Navigate → **Table view** (of `TABLE` command) |
| `NAV + UP` | chord | Navigate → **Groove view** |
| `NAV + PLAY` | chord | Start phrase with retrig (`PM_PHRASE`) |
| `NAV + ALT` | chord, either order | Un-mute all |
| `NAV + NAV` | double tap | Switch to the **piano roll view** of the same phrase |
| `PLAY` | chord | Start phrase playback (`PM_PHRASE`) |
| `DOWN / UP / LEFT / RIGHT` | chord | Move cursor |

*On release*

| Release | Action |
|---------|--------|
| any button, once `ENTER` is no longer held | Stop note audition (`stopAudition`); normally this is the release of `ENTER` itself |

### 3.3.1 `PianoRollView` (`Views/PianoRollView.cpp`) — work in progress

Alternative view of the current phrase (`viewData_->currentPhrase_`), reached from the phrase
view with `NAV + NAV`. It draws a piano keyboard (column 0, `gchar_vertical_piano`, the key of the cursor
is drawn selected), the note labels (column 4, rows 3–18, 16 notes; notes that are not part of the scale and key of the project are `Theme::View::inactive`), the step index `0`–`F` (row 2), the note
grid (columns 8–23, one column per step), scroll indicators and, in the info area at the bottom, the notes that
play (`drawNotes`, as in the phrase view). It has a cursor (a step and a note). To the right of the grid
(column 25) it shows the titles and values of the step under the cursor (note, instrument, volume, command 1 and 2
with their parameters, in the formats and colors of the phrase view). While the grid has the focus the
fields show what is in effect at the step: a value the step does not have itself is the one set before it
and is drawn `Theme::View::inactive`. Values are sticky until a new note or a note off comes in (the values of
the step of that note still count, what was set before it does not); a note that is still sounding is shown
as the sticky note (until a note off), a parameter stays with its command. In the fields themselves only the
values of the step are shown. The exception is the instrument: a step without one shows the instrument that is in
effect (the last one set at or before it, which does not end at a note, as in the phrase view and the preview, the
"shadow instrument") drawn `Theme::View::inactive`, in the fields as well (`--` only if there is none).

Under the fields (column 25, rows 13–14) a static help shows how to get to the part that does not have the
focus: `ALT + RIGHT` "Fields" while the grid has it, `ALT + LEFT` "Grid" while the fields have it
(`char_key_alt_s`, `char_key_right_s` / `char_key_left_s`).

The step index is colored like the row numbers of the phrase view (the first step of every phrase division is
highlighted). All steps at or after the global phrase length (`VarPhraseLength`) are `Theme::View::inactive`,
in the index and in the grid (the cursor cell keeps the selection background).

## 5. Sample views

### 5.1 `SampleEditorView` (`Views/SampleEditorView.cpp`)

The start and the end of the sample are markers on the graph, as the slice points of the sample slicer (§5.2). The
**Marker** field below the graph selects the current one, **Start** or **End** (`ENTER + LEFT / RIGHT` on the field);
the start, the end and the zoom (`Zoom 02x/05x`, the zoom level of the maximum) are shown below it, and a legend on the
right. The Marker field has the focus when the view opens; the graph is not a field to focus. The start stays before the end. Below the zoom
the title **Operations** is followed by the buttons of the operations in a row (**Trim**, **Peak Normalize**, `ENTER` asks to apply it to the selection), the buttons of the file are in the bottom
row (**Save**, **Save & Load** unless a sample of the pool is edited, **Discard**); the first one starts at column 1,
the cap of a button is left of it. Selecting the other marker, or moving the current one, scrolls the waveform so that the marker is visible. The markers are always on the screen, also at the very first and last sample.

| Combination | Type | Action |
|-------------|------|--------|
| `NAV + LEFT` | chord | Navigate → back to source view (`vtCollapse`) |

| `EDIT + ENTER + LEFT / RIGHT` | chord | Move the current marker to the next **zero crossing** to the left / right (the left channel, read from the file, see §5.2 for what a zero crossing is). Without another zero crossing it moves to the start / the last sample. It does not pass the other marker |
| `EDIT + UP` | chord | Zoom in (`adjustZoom(+1)`), down to one sample per pixel (the last zoom level, always reachable; a sample with fewer samples than pixels does not zoom, every sample is wider than a pixel already) |
| `EDIT + DOWN` | chord | Zoom out (`adjustZoom(-1)`) |
| `ENTER + EDIT` | chord | On the Marker field: it selects Start again, the markers stay where they are. On the other fields it resets them |
| `PLAY` (hold) | chord | Start sample playback / streaming; **release stops** |
| bare arrows | chord | Field navigation (§2.1) |

## 8. Appendix

- **View-mode semantics** (`ViewMode` in `View.h`): `VM_NEW`, `VM_CLONE` and
  `VM_SELECTION` arm an action for the *next* press.
- **Mute and solo** (`UIController::BeginMute` / `BeginSolo` / `OnButtonUp`, the
  same in the song, chain, phrase and mixer view): `EDIT + NAV` toggles the mute of the
  channel (the selected channels in the song view), `ENTER + NAV` solos it. Both
  work while held: letting go of `EDIT` / `ENTER` while `NAV` is still held takes it back
  (the mutes from before the solo are restored), letting go of `NAV` first keeps it.
  While the chord is held the `SoloMute` legend is shown.
  Other buttons pressed or released in between change nothing. A kept solo ends with
  the next `ENTER + NAV` (which restores the mutes from before it) or with `NAV + ALT`
  (un-mute all).
- **Exact chords**: a chord only fires for its exact held set, so extra held
  buttons (including a second direction) suppress it. Modal dialogs opened
  mid-chord (`MessageBox`, `CommandView`) deliberately ignore other held buttons.
- **Key repeat**: held directions are re-sent as `ButtonDown(direction, mask)`,
  so `UP` held with `ENTER` keeps adjusting a value, but holding `RIGHT` and
  tapping `UP` does nothing.
- **Navigation convention**: `NAV + direction` always jumps to a sibling view;
  `NAV + PLAY` starts playback with retrig; `PLAY` alone starts without retrig.
- **Field views** additionally inherit `FieldView` (§2.1): `ENTER+arrow` edits a
  value, `ENTER+EDIT` resets it, `EDIT` alone opens the edit context.
- **Import list views** inherit `FileListView` (§2.3): `EDIT+UP/DOWN` page,
  `ENTER` enter, `NAV+LEFT` back.
