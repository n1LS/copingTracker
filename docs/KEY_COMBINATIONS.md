# copingTracker — Key Combinations Reference

This document lists every key / key combination handled by the UI **view classes**
(`sources/Application/Views/**`). It was generated by reading every
`ButtonDown()` / `ButtonUp()` / `OnButtonOverride()` implementation in the codebase.

Input is expressed as a **button event** (`ButtonMask` in
`BaseClasses/View.h`). Every press (and every auto-repeat of a held direction)
calls `ButtonDown(newButton, mask)`: `newButton` is the single button that
triggered the event and `mask` holds the *other* buttons already held (never
`newButton` itself). Every release calls `ButtonUp(button, mask)` with the
released button and what is still held afterwards.

A chord is matched **exactly**: `newButton` plus the exact set of held buttons
(`IsChord(newButton, mask, trigger, held)`). `EDIT+UP` means UP pressed while
only EDIT is held. A combination no view defines does nothing, so holding
RIGHT and pressing UP no longer moves in two directions at once and a second
direction is ignored.

Chords made only of ALT / NAV / EDIT have no natural trigger, so either key may
be the last one pressed (`IsPair(...)`): `EDIT+ALT`, `EDIT+NAV`, `NAV+ALT`,
`NAV+EDIT`. These are
marked *either order* below. Everything else is triggered by ENTER, PLAY or a
direction.

In the tables, **Type** is `chord` (exact match), `chord, either order`, or
`release` (fires from `ButtonUp`).

## 1. Button / Host-key reference

| Device button | Bit / constant | Host keyboard key |
|---------------|----------------|-------------------|
| UP            | `BM_UP`    (1<<3) | `↑` (Up arrow)        |
| DOWN          | `BM_DOWN`  (1<<1) | `↓` (Down arrow)      |
| LEFT          | `BM_LEFT`  (1<<0) | `←` (Left arrow)      |
| RIGHT         | `BM_RIGHT` (1<<2) | `→` (Right arrow)     |
| ALT           | `BM_ALT`   (1<<4) | `A`                   |
| NAV           | `BM_NAV`   (1<<7) | `S`                   |
| EDIT          | `BM_EDIT`  (1<<5) | `E`                   |
| ENTER         | `BM_ENTER` (1<<6) | `D`                   |
| PLAY          | `BM_PLAY`  (1<<8) | `Space`               |

> Host mapping lives in `sources/Adapters/Host/system/input.cpp` (`scanKeys()`).
> On the device the same buttons are physical keys / virtual (mirrorUI) buttons.

In the tables below a **modifier** is one of `ALT`, `NAV`, `EDIT`, `ENTER`;
a **direction** is one of `UP`, `DOWN`, `LEFT`, `RIGHT`.

## 2. Shared base-class behavior

These are wired once in the base classes and inherited by many views. Specific
views add their own handling on top (see per-view sections).

### 2.1 `FieldView` (`BaseClasses/FieldView.cpp`) — used by Instrument, Device,
Master, Modulation, Project, Theme, Mixer, SampleEditor, SampleSlices, etc.

| Combination | Type | Action |
|-------------|------|--------|
| `ENTER` alone | chord + release | Press the focused field (fires `OnClick()` on release, or opens the text editor if the field wants one) |
| `ENTER + direction` | chord | Adjust the focused field's value (`ProcessArrow`) |
| `ENTER + EDIT` | chord, either order | Clear / reset the field value (`ProcessClear`) |
| `EDIT` alone | release | Edit-click on the focused field (fires `OnEditClick()` on release) |
| `EDIT + direction` | chord | Field-specific fine edit (`ProcessEditArrow`, e.g. `UITempoField`) |
| bare `UP / DOWN / LEFT / RIGHT` | chord | Move field focus (vertical / horizontal adjacency) |

### 2.2 `ListView` (`BaseClasses/ListView.cpp`) — generic list base

| Combination | Type | Action |
|-------------|------|--------|
| `UP` | chord | Move up one item |
| `ALT + UP` | chord | Page up (via `HandleUp(page=true)`) |
| `DOWN` | chord | Move down one item |
| `ALT + DOWN` | chord | Page down |
| `ENTER` | chord | `HandleEnter()` (activate item) |
| `EDIT` | chord | `HandleEdit()` (edit item) |

### 2.3 `FileListView` (`BaseClasses/FileListView.cpp`) — base for
`InstrumentImportView`, `ThemeImportView`, `SelectProjectView`, `SampleImportView`

| Combination | Type | Action |
|-------------|------|--------|
| `UP` | chord | Move up one item |
| `EDIT + UP` | chord | Page up |
| `DOWN` | chord | Move down one item |
| `EDIT + DOWN` | chord | Page down |
| `ENTER` | chord | `HandleEnter()` — enter directory / activate item |
| any button pressed while `ENTER` is held | chord | Consumes the pending directory-enter so it does **not** fire on release |
| `EDIT` alone | chord | `HandleEdit()` — open editor for the selected item |
| `NAV + LEFT` | chord | `HandleBackNavigation()` (leave list / go back) |
| `LEFT / RIGHT` | chord | Tabs (`HasTabSelection()`) or bottom buttons (`HasButtonSystem()`) |
| `ENTER` release | release | Open the selected directory / `..` parent (enter-on-release) |

> Subclass `SampleImportView` adds more combos — see §14.

### 2.4 Value fields (`UIIntField`, `UIIntVarField`, `UIHexVarField`, ...)
Generic value editing reached through `FieldView`:
`ENTER+arrow` = change value, `ENTER+EDIT` = reset to default (only when modified).

## 8. Appendix

- **View-mode semantics** (`ViewMode` in `View.h`): `VM_NEW`, `VM_CLONE` and
  `VM_SELECTION` arm an action for the *next* press; `VM_MUTEON` / `VM_SOLOON`
  are "hold"-type arms resolved when `NAV` is released (so `EDIT+NAV` /
  `ENTER+NAV` are effectively *hold NAV* to mute / solo).
- **Exact chords**: a chord only fires for its exact held set, so extra held
  buttons (including a second direction) suppress it. Modal dialogs opened
  mid-chord (`MessageBox`, `CommandView`) deliberately ignore other held buttons.
- **Key repeat**: held directions are re-sent as `ButtonDown(direction, mask)`,
  so `UP` held with `ENTER` keeps adjusting a value, but holding `RIGHT` and
  tapping `UP` does nothing.
- **Navigation convention**: `NAV + direction` always jumps to a sibling view;
  `NAV + PLAY` starts playback with retrig; `PLAY` alone starts without retrig.
- **Field views** additionally inherit `FieldView` (§2.1): `ENTER+arrow` edits a
  value, `ENTER+EDIT` resets it, `EDIT` alone opens the edit context.
- **Import list views** inherit `FileListView` (§2.3): `EDIT+UP/DOWN` page,
  `ENTER` enter, `NAV+LEFT` back.
